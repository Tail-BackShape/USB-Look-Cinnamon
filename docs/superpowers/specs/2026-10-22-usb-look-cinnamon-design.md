# USB-Look-Cinnamon 設計仕様

- 版: 1.0（設計承認済み・実装前）
- 日付: 2026-10-22
- 対象: Linux Mint / Cinnamon 6.6.7 を優先し、Cinnamon 6.xへ拡張可能な構成
- リポジトリ: https://github.com/Tail-BackShape/USB-Look-Cinnamon
- ライセンス: MIT

## 1. 目的と境界

USB-Look-Cinnamonは、Cinnamonパネルに常駐する軽量なUSBデバイス監視Appletである。USB機器全般の接続状態、識別情報、種類別の使用状態を閲覧する。特にUSBシリアルポートを開いているプロセス名とPIDを、権限とLinuxの可観測性が許す範囲で表示する。

### 必須要件

1. USB機器全般（USBシリアル、デバッグ、ストレージ、HID、カメラ、オーディオ、USBネットワーク、ハブ、その他）を列挙する。
2. 監視対象のON/OFFは**種類別のみ**とし、個々の機器の例外設定は設けない。
3. VID/PID、製品名、製造元、USBパス、カーネルドライバ、機器が提供するデバイスノードを取得可能な範囲で表示する。
4. デバイスの接続・切断はudevイベント駆動で追従する。
5. Cinnamonのシステムフォント、シンボリックアイコン、ライト／ダークテーマを継承する。
6. 列挙・判定・表示の失敗でCinnamonセッションを停止させず、取得不能な項目は明示する。
7. 外部通信を必須とせず、一般ユーザー権限かつ読み取り専用で動作する。

### 非目標

- 開発ボードとIDEプロジェクトの紐付け
- USB機器のリセット、切断、認可変更、強制アンマウント、ファーム書き込み
- USBシリアルを監視目的で開くこと、通信データの取得
- プロセス終了や権限昇格
- Cinnamon以外のデスクトップ環境への初期対応

## 2. デバイスモデル

Linuxのudev/GUdevを通じ、USBサブシステムの物理デバイス（DEVTYPE=usb_device）と、その子インターフェース（DEVTYPE=usb_interface）を関連付ける。USBルートハブは通常の件数・一覧から除外し、外付けハブと配下のデバイスは扱う。

一つの物理USB機器は一覧に一行だけ表示する。複合デバイスは複数カテゴリに所属できるが、どれか一つのカテゴリがONなら一覧に一度だけ表示する。展開時に個々のインターフェースとデバイスノードを示す。カテゴリの判定はUSBインターフェースクラス、udevの属性、既知のドライバ情報を組み合わせ、分類不能な場合は「その他」に分類する。USBデバッグ機器のすべてを自動識別できる保証はしない。

セッション内の同一性判定はsysfsのパスと接続イベントを基に行う。デバイスシリアル番号の永続保存や、接続機器の追跡データベースは設けない。

## 3. 占有・利用状態の意味

USB機器全般に一律の排他的「空き／使用中」判定は成立しない。表示ラベルと根拠を種類別に定める。

| 種類 | 判定・表示 | 制限 |
| --- | --- | --- |
| USBシリアル | 対象ttyを開くプロセス名/PIDを検出した場合Busy。検出されなければNot in use | 未検出でも将来の利用可能性は保証しない |
| カメラ等の文字デバイス | 対応デバイスノードに対する検出可能なプロセスの開放状態を表示 | PipeWire等を介した実ユーザーを常に識別できるとは限らない |
| ストレージ | マウント状態とマウントポイントを表示 | Mountedは「占有」を意味しない |
| HID、音声、ネットワーク、デバッグ等 | インターフェース、ドライバ、取得可能な利用情報を表示 | ドライバへのバインドだけでBusyと決めない |
| 任意の機器 | 判定権限や情報が不足すればUnknown | Unknownを空き扱いしない |

占有検出は、Linuxのプロセスファイルディスクリプタとデバイスノードの照合など、非破壊的な方法を使用する。他ユーザーのプロセスの可視性や動作中の状態変化には限界がある。詳細プローブは非同期で実行し、パネル描画をブロックしない。

## 4. パネルとポップアップ

### パネル

- システムのUSBシンボリックアイコンを表示する。
- 有効カテゴリに属する物理USB機器数を表示する（設定でOFFにできる）。
- USB列挙不能等の重大エラーは警告表示する。
- **占有件数はポップアップ表示中の新鮮な検査結果のみ表示する。閉じた後は占有走査を停止し、古い占有件数を現在値として表示しない。** このルールで「閉じている間は占有走査しない」という省リソース要件との整合性を保つ。

### ポップアップ

- 左クリックで表示／非表示。
- 製品名・VID/PID・ポート名による絞り込み。
- 種類ごとに折りたためる一覧。複合デバイスの表示は重複させない。
- デバイス行クリックで識別情報、USBインターフェース、対応デバイスノード、利用状態の根拠、検出できたプロセス名/PIDを展開する。
- デバイス行のコンテキスト操作はパスやVID/PIDのクリップボードへのコピーに限定する。
- パネル右クリックはCinnamonの標準メニューと設定への導線を維持する。

接続・切断通知は設定で切り替え、初期値をOFFとする。切断時は一覧を直ちに更新し、当該機器への進行中の検査結果を破棄する。

## 5. 種類別設定

CinnamonのApplet設定APIとsettings-schema.jsonを用いる。カテゴリは次の九つとし、初期値はすべてON。

1. USBシリアル
2. デバッグ機器
3. ストレージ
4. HID（キーボード・マウス等）
5. カメラ
6. オーディオ
7. USBネットワーク
8. USBハブ
9. その他

その他の設定は「パネルに機器数を表示」（初期ON）、「接続・切断通知」（初期OFF）とする。個別機器トグル、フォント選択、独自テーマ設定は設けない。

種類別トグルOFFは一覧・通知・占有検査から除外することを意味するが、設定を後から変更できるように最低限のUSB列挙は続ける。設定はCinnamonの機構によってセッションをまたいで保持する。

## 6. ソフトウェア構成

初期版はCinnamonのCJS/JavaScriptとGUdevのGObject Introspection APIを中心に実装する。常駐する追加デーモン、Python仮想環境、独自ビルド済みバイナリ、ネットワークサービスは要件にしない。GUdevなどの実行時依存はディストリビューションのパッケージとして明示する。

内部責務を次に分ける。

- DeviceRegistry: GUdevによる初期スナップショット、uevent購読、物理機器とインターフェースの対応、差分通知
- DeviceClassifier: USBクラスとudev属性による種類の集合への分類
- UsageInspector: 対象ノードの読み取り専用・非同期占有検査、権限不足/不明の区別
- SettingsController: 種類別フィルタ、件数表示、通知設定
- PanelView / PopupView: Cinnamon標準UI、検索、詳細表示、表示キャッシュ
- NotificationController: 有効なカテゴリに属する機器の接続・切断通知

追加・切断イベントは短時間の変化をまとめて差分更新し、CPU負荷を抑える。プロセス走査はポップアップ表示中に限り、選択対象を絞り、少なくとも数秒の間隔を設ける。閉じたら関連するタイマーを停止する。Applet削除・Cinnamon再起動時には購読、タイマー、非同期処理を解除または無効化する。

## 7. エラー・安全・プライバシー

- 製品名・メーカー・シリアル・デバイスノードが欠損してもクラッシュしない。取得済み項目のみ表示する。
- 機器が検査中に外された場合は結果を採用しない。
- GUdev利用不能時は分かるエラーを表示し、パネルの描画処理は継続する。
- 権限不足、コマンド非搭載、検出対象なしを区別し、推測したプロセス名を出さない。
- USB製品文字列など外部由来文字列をコードとして評価しない。シェル引数を文字列連結で組み立てない。
- デバイスのシリアル番号やプロセス情報を外部送信しない。ログは最小限とし、報告用の例示データを匿名化する。
- USB機器の操作、権限変更、強制解放は実装しない。

## 9. 検証と受け入れ基準

### 自動テスト

1. 初期一覧の重複排除、複合デバイスのインターフェース集約
2. 九カテゴリのON/OFFと複合カテゴリのOR判定
3. udevのadd/remove/changeイベント、連続接続・切断
4. 欠損文字列、無効なVID/PID、デバイスノードなし
5. 占有検査でのBusy、Not in use、Unknown、権限不足の分岐
6. 切断直後や設定変更直後に戻る古い非同期結果の破棄
7. ポップアップ閉鎖・Applet削除時のタイマーと購読の解放
8. 機器数と占有件数の新鮮さの整合性

ハードウェアがないCIでは匿名化したudev/プロセス情報のfixtureを使う。

### 実機テスト

Linux Mint / Cinnamon 6.6.7でUSB-UART、CDC ACM、ストレージ、HID、ハブ、可能ならデバッグ機器とカメラを用いて動作を確認する。接続の連打、同型複数機器、ポート番号の再割り当て、占有するプロセスの開始・終了、パネルの複数配置、ライト/ダーク切り替え、セッション再起動を含める。

監視によって機器をリセットせず、未使用時に継続的なプロセス走査を行わないことを計測またはログで確認する。メモリとCPUはApplet導入前後のCinnamonプロセスを比較するが、共有プロセスのため絶対値をApplet単独の使用量と断定しない。
